## Lessons for future briefs
1. Say what to do when a number is missed.
2. Give a run time for slow commands, and run them once.
3. Put the secret rule in the brief's own rules.
4. Name the base branch.
5. Quote third-party limits from docs or a measured call.
6. Name functions and tests, not line numbers; a mutation check restores the file.
7. Ground a plan's state table in the queue and the ledger, and mark it as a snapshot.
